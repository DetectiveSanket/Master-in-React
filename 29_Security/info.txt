1️⃣ ⁡⁣⁢⁣𝗫𝗦𝗦 𝗣𝗿𝗲𝘃𝗲𝗻𝘁𝗶𝗼𝗻 (𝗖𝗿𝗼𝘀𝘀-𝗦𝗶𝘁𝗲 𝗦𝗰𝗿𝗶𝗽𝘁𝗶𝗻𝗴)⁡

    XSS = malicious code injection into your website (e.g., <script> tags).
    If user input is not sanitized, it can be used to steal cookies or modify DOM.

    🧠 Theory

        XSS Attack Example:
        User enters <script>alert('Hacked!')</script> in a comment box → browser executes it → your site is compromised.

    ✅ Solution in React

        React escapes (sanitizes) text by default, so normal usage is safe:

           ⁡⁢⁣⁣ ⁡⁢⁢⁢export default function Comment({ text }) {
              return <p>{text}</p>;  // React escapes text automatically ✅
            }⁡

    ❌ Unsafe Case (Direct HTML Injection)

        <div dangerouslySetInnerHTML={{ __html: userInput }} />

        ⚠️ Only use dangerouslySetInnerHTML if you sanitize input first.

    🛠 Tools

        DOMPurify → sanitize HTML safely:

            npm install dompurify

            import DOMPurify from 'dompurify';
            <div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(userInput) }} />

2️⃣ ⁡⁣⁢⁣𝗖𝗦𝗥𝗙 𝗣𝗿𝗼𝘁𝗲𝗰𝘁𝗶𝗼𝗻 (𝗖𝗿𝗼𝘀𝘀-𝗦𝗶𝘁𝗲 𝗥𝗲𝗾𝘂𝗲𝘀𝘁 𝗙𝗼𝗿𝗴𝗲𝗿𝘆)⁡

    🧠 Theory

        CSRF = attacker tricks user’s browser to send requests on their behalf.
        Example:

            You’re logged into a bank site.
            Attacker sends you a malicious link → browser sends your cookies → money transfer is made.

    ✅ Solution

        Use CSRF Tokens:

            - Backend generates a unique token per session.
            - React app includes this token in POST/PUT/DELETE requests.
            - Server validates token before processing.

        Example with Axios:

            ⁡⁢⁢⁢import axios from "axios";

            axios.post("/api/transfer", data, {
              headers: { "X-CSRF-Token": csrfTokenFromServer },
            });⁡

        Most modern frameworks (Django, Laravel, Spring) have CSRF protection built-in.

3️⃣ ⁡⁣⁢⁣𝗜𝗻𝗽𝘂𝘁 𝗦𝗮𝗻𝗶𝘁𝗶𝘇𝗮𝘁𝗶𝗼𝗻⁡

    🧠 Why

        Attackers often try SQL Injection, XSS, or script injection via forms.

    ✅ Solution

        Validate input on both frontend + backend

        Example: Email validation

            ⁡⁢⁢⁢const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
            if (!emailRegex.test(userEmail)) {
              alert("Invalid email address!");
            }⁡

        But never trust frontend validation alone → must validate on backend too.

4️⃣ ⁡⁣⁢⁣𝗦𝗲𝗰𝘂𝗿𝗲 𝗖𝗼𝗱𝗶𝗻𝗴 𝗣𝗿𝗮𝗰𝘁𝗶𝗰𝗲𝘀⁡

    ✅ Checklist

        🔹 Avoid storing secrets in frontend
            ❌ Don’t put API keys directly in code.
            ✅ Use .env and hide them with backend proxy.

        🔹 Use HTTPS
            Always serve your app over HTTPS in production.

        🔹 Use Helmet (for backend)
            If you have Node/Express backend:

                npm install helmet

                import helmet from "helmet";
                app.use(helmet());

            Helmet sets secure HTTP headers.

        🔹 Avoid eval()
            Never use eval() — attackers can inject malicious JS.

        🔹 Keep dependencies updated
            Run npm audit regularly and fix vulnerabilities:

                npm audit fix
