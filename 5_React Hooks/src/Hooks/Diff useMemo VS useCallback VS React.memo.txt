============================================================
        useMemo vs useCallback vs React.memo
        Simple, Clear, and Real-World Difference Guide
============================================================

These 3 topics confuse almost every React learner at first.

Why?

Because all 3 are related to PERFORMANCE OPTIMIZATION, but they solve
different problems.

The easiest way to remember them is:

1. useMemo     -> memoizes a VALUE
2. useCallback -> memoizes a FUNCTION
3. React.memo  -> memoizes a COMPONENT

------------------------------------------------------------
1) ONE-LINE DEFINITION
------------------------------------------------------------

useMemo:
- Stores the result of a calculation so React does not recalculate it
  on every render unless dependencies change.

useCallback:
- Stores the function reference so React does not recreate the function
  on every render unless dependencies change.

React.memo:
- Prevents a component from re-rendering if its props have not changed.

------------------------------------------------------------
2) SUPER SHORT MEMORY TRICK
------------------------------------------------------------

- useMemo     = "Remember the result"
- useCallback = "Remember the function"
- React.memo  = "Remember the component output if props are same"

------------------------------------------------------------
3) MAIN DIFFERENCE TABLE
------------------------------------------------------------

+--------------+---------------------------+----------------------------------+----------------------------------+
| Feature      | What it memoizes          | Main purpose                     | Used when                        |
+--------------+---------------------------+----------------------------------+----------------------------------+
| useMemo      | Computed value            | Avoid expensive recalculation    | Heavy calculation / derived data |
| useCallback  | Function reference        | Avoid recreating function        | Passing callbacks to child       |
| React.memo   | Entire component render   | Avoid unnecessary re-render      | Child gets same props often      |
+--------------+---------------------------+----------------------------------+----------------------------------+

------------------------------------------------------------
4) ⁡⁢⁣⁣𝗧𝗛𝗘 𝗕𝗜𝗚 𝗜𝗗𝗘𝗔⁡
------------------------------------------------------------

React components re-render often.

That is NORMAL.

But sometimes re-rendering or recalculating becomes expensive.

That is where these tools help.

Important:
These are optimization tools, NOT tools to make code "more correct".

Do NOT use them everywhere blindly.

------------------------------------------------------------
5) ⁡⁢⁣⁣𝘂𝘀𝗲𝗠𝗲𝗺𝗼 𝗜𝗡 𝗗𝗘𝗧𝗔𝗜𝗟⁡
------------------------------------------------------------

⁡⁣⁢⁣What it does:⁡
- It remembers the result of a calculation.
- React recalculates only when dependencies change.

Syntax:

⁡⁢⁢⁢const memoizedValue = useMemo(() => {
  return expensiveCalculation(data);
}, [data]);⁡

⁡⁣⁢⁣Best use cases⁡:
- Filtering a huge list
- Sorting large data
- Heavy calculations
- Creating derived objects/arrays that should not change unnecessarily

Example 1: Expensive calculation

⁡⁢⁢⁢import { useMemo, useState } from "react";⁡

⁡⁢⁢⁢function PriceCalculator() {
  const [count, setCount] = useState(0);
  const [price, setPrice] = useState(100);

  const discountedPrice = useMemo(() => {
    console.log("Calculating discount...");
    return price - price * 0.1;
  }, [price]);

  return (
    <div>
      <h2>Discounted Price: {discountedPrice}</h2>
      <button onClick={() => setCount(count + 1)}>
        Re-render Count: {count}
      </button>
      <button onClick={() => setPrice(price + 50)}>
        Increase Price
      </button>
    </div>
  );
}⁡

⁡⁣⁢⁣Explanation:⁡
- Clicking "Re-render Count" changes only count.
- Without useMemo, the discount calculation would run every render.
- With useMemo, it runs only when price changes.

⁡⁣⁢⁣Real-life use case:⁡
- E-commerce product filtering
- Dashboard analytics data calculations
- Search result sorting
- Invoice total calculations

------------------------------------------------------------
6) ⁡⁢⁣⁣𝘂𝘀𝗲𝗖𝗮𝗹𝗹𝗯𝗮𝗰𝗸 𝗜𝗡 𝗗𝗘𝗧𝗔𝗜𝗟⁡
------------------------------------------------------------

What it does:
- It remembers the function itself.
- React returns the same function reference unless dependencies change.

Syntax:

⁡⁢⁢⁢const memoizedFunction = useCallback(() => {
  doSomething();
}, [dependencies]);⁡

Best use cases:
- Passing callback functions to child components
- Avoiding unnecessary child re-renders
- Stable event handlers in optimized components

Example 2: Passing function to child

⁡⁢⁢⁢import React, { useCallback, useState } from "react";

const Child = React.memo(({ onClick }) => {
  console.log("Child rendered");
  return <button onClick={onClick}>Click Me</button>;
});

function Parent() {
  const [count, setCount] = useState(0);

  const handleClick = useCallback(() => {
    console.log("Button clicked");
  }, []);

  return (
    <div>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>Increase Count</button>
      <Child onClick={handleClick} />
    </div>
  );
}⁡

Explanation:
- Parent re-renders when count changes.
- Normally, a new handleClick function is created on every render.
- Because of that, Child would think props changed.
- useCallback keeps the same function reference.
- Since Child is wrapped with React.memo, Child will not re-render unnecessarily.

Real-life use case:
- Passing event handlers to table rows
- Sending action functions to memoized cards/components
- Optimized forms
- Large UI trees with many child components

------------------------------------------------------------
7) ⁡⁢⁣⁣𝗥𝗲𝗮𝗰𝘁.𝗺𝗲𝗺𝗼 𝗜𝗡 𝗗𝗘𝗧𝗔𝗜𝗟⁡
------------------------------------------------------------

What it does:
- ⁡⁣⁣⁢It prevents a functional component from re-rendering if props stay the same.⁡

Syntax:

const MemoizedComponent = React.memo(Component);

Best use cases:
- Child components receive same props frequently
- Large lists
- Reusable UI components
- Expensive child renders

Example 3: Component re-render control

⁡⁢⁢⁢import React, { useState } from "react";

const UserCard = React.memo(({ name }) => {
  console.log("UserCard rendered");
  return <h3>User: {name}</h3>;
});

function App() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <UserCard name="Sanket" />
      <button onClick={() => setCount(count + 1)}>
        Count: {count}
      </button>
    </div>
  );
}⁡

Explanation:
- App re-renders whenever count changes.
- But UserCard receives the same name prop every time.
- React.memo skips re-rendering UserCard.

Real-life use case:
- Product card
- User profile card
- Sidebar item
- Chart wrapper
- Reusable preview components

------------------------------------------------------------
8) ⁡⁢⁣⁣𝗠𝗢𝗦𝗧 𝗜𝗠𝗣𝗢𝗥𝗧𝗔𝗡𝗧 𝗥𝗘𝗟𝗔𝗧𝗜𝗢𝗡 𝗕𝗘𝗧𝗪𝗘𝗘𝗡 𝗧𝗛𝗘𝗠⁡
------------------------------------------------------------

These 3 are often used together.

Example idea:

- React.memo protects the child component
- useCallback keeps callback prop stable
- useMemo keeps computed value stable

Simple thinking:

Parent component:
- calculates data -> useMemo
- creates event handler -> useCallback
- sends props to child

Child component:
- wrapped with React.memo

That is the most common optimization pattern.

------------------------------------------------------------
9) REAL-TIME PRACTICAL EXAMPLE
------------------------------------------------------------

Imagine an E-commerce Product Page:

Parent component does:
- filter products
- sort products
- pass "Add to Cart" function to each ProductCard

Without optimization:
- Every parent re-render re-filters products
- Every parent re-render creates new function references
- Every ProductCard re-renders again

With optimization:
- useMemo -> filteredProducts
- useCallback -> handleAddToCart
- React.memo -> ProductCard

Example:

import React, { useMemo, useCallback, useState } from "react";

const ProductCard = React.memo(({ product, onAddToCart }) => {
  console.log("Rendered:", product.name);

  return (
    <div>
      <h3>{product.name}</h3>
      <button onClick={() => onAddToCart(product.id)}>
        Add to Cart
      </button>
    </div>
  );
});

function ProductList({ products }) {
  const [search, setSearch] = useState("");
  const [cartCount, setCartCount] = useState(0);

  const filteredProducts = useMemo(() => {
    return products.filter((p) =>
      p.name.toLowerCase().includes(search.toLowerCase())
    );
  }, [products, search]);

  const handleAddToCart = useCallback((id) => {
    console.log("Added product:", id);
    setCartCount((prev) => prev + 1);
  }, []);

  return (
    <div>
      <h2>Cart: {cartCount}</h2>

      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search products"
      />

      {filteredProducts.map((product) => (
        <ProductCard
          key={product.id}
          product={product}
          onAddToCart={handleAddToCart}
        />
      ))}
    </div>
  );
}

What happens here?
- useMemo prevents unnecessary filtering
- useCallback prevents new function creation every render
- React.memo prevents ProductCard from re-rendering if props are unchanged

This is a REAL and very common production-level use case.

------------------------------------------------------------
10) EASY ANALOGY
------------------------------------------------------------

Imagine a kitchen:

useMemo:
- You already prepared sauce once.
- If ingredients don't change, reuse the same sauce.
- No need to cook it again.

useCallback:
- You keep the same recipe card.
- Instead of writing a new recipe every time, you reuse the same one.

React.memo:
- If the order is the same, no need to cook the same dish again.

------------------------------------------------------------
11) WHEN TO USE WHAT
------------------------------------------------------------

Use useMemo when:
- You have expensive calculations
- You want to memoize derived values
- You want stable arrays/objects in some cases

Use useCallback when:
- You pass functions to child components
- Child component is memoized
- Function recreation causes unnecessary re-renders

Use React.memo when:
- Component re-renders often with same props
- Component render is expensive
- You want to optimize child rendering

------------------------------------------------------------
12) WHEN NOT TO USE THEM
------------------------------------------------------------

Do NOT use them when:
- Your app is already fast
- Calculation is very small
- Component is tiny and cheap
- You are adding optimization without any actual problem
- The code becomes harder to read for no reason

Important:
Overusing memoization can make code more complex and sometimes even slower.

Optimization should be done only when needed.

------------------------------------------------------------
13) COMMON MISTAKES
------------------------------------------------------------

Mistake 1:
Using useMemo for everything
- Not every value needs memoization

Mistake 2:
Using useCallback for every function
- Small functions usually do not need it

Mistake 3:
Using React.memo but still passing new objects/functions every render
- Then React.memo may not help much

Mistake 4:
Thinking memoization stops all renders
- It only helps in specific cases

Mistake 5:
Forgetting dependency arrays
- Wrong dependencies can create bugs or stale values

------------------------------------------------------------
14) VERY IMPORTANT POINT ABOUT REFERENCES
------------------------------------------------------------

In JavaScript:

{} !== {}
[] !== []
() => {} !== () => {}

Why does that matter?

Because React compares props by reference in many optimization cases.

So even if two objects look same, React may treat them as different if they
are newly created.

Example:

const user = { name: "Sanket" };

If this object is created again on every render, React.memo may still re-render
the child because the object reference changes.

This is one reason useMemo can help with objects/arrays too.

Example:

const user = useMemo(() => ({ name: "Sanket" }), []);

15) DIFFERENCE IN ONE CODE VIEW
------------------------------------------------------------

import React, { useMemo, useCallback, useState } from "react";

const Child = React.memo(({ items, onPrint }) => {
  console.log("Child rendered");

  return (
    <div>
      <p>{items.join(", ")}</p>
      <button onClick={onPrint}>Print</button>
    </div>
  );
});

function App() {
  const [count, setCount] = useState(0);

  const items = useMemo(() => ["React", "Hooks", "Memo"], []);
  const handlePrint = useCallback(() => {
    console.log("Printing...");
  }, []);

  return (
    <div>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>Increase</button>
      <Child items={items} onPrint={handlePrint} />
    </div>
  );
}

Here:
- useMemo -> keeps items array stable
- useCallback -> keeps handlePrint stable
- React.memo -> stops Child from re-rendering if props stay same

------------------------------------------------------------
16) QUICK INTERVIEW-STYLE DIFFERENCE
------------------------------------------------------------

Q: What is the difference between useMemo and useCallback?

Answer:
- useMemo returns a memoized value
- useCallback returns a memoized function

Q: What is the difference between useCallback and React.memo?

Answer:
- useCallback memoizes a function
- React.memo memoizes a component render

Q: Can useCallback work without React.memo?

Answer:
- Yes, but it is most useful when passing functions to memoized children

Q: Can React.memo alone solve all re-render problems?

Answer:
- No, because if props change every render, React.memo cannot help much

------------------------------------------------------------
17) FINAL COMPARISON IN SIMPLE LANGUAGE
------------------------------------------------------------

useMemo:
- "Don't recalculate this value unless needed."

useCallback:
- "Don't recreate this function unless needed."

React.memo:
- "Don't re-render this component unless props changed."

------------------------------------------------------------
18) BEST PRACTICE FORMULA
------------------------------------------------------------

If child re-render problem exists:

Step 1:
Wrap child with React.memo

Step 2:
If child receives function prop, wrap function with useCallback

Step 3:
If child receives calculated array/object/value, wrap it with useMemo

This is the practical formula many React developers use.

20) FINAL TAKEAWAY
------------------------------------------------------------

If you remember only one thing, remember this:

- useMemo = memoize calculated VALUE
- useCallback = memoize FUNCTION
- React.memo = memoize COMPONENT

They are not the same.
They work at different levels.
They are used for optimization only when really needed.

Simple rule:
- expensive value? -> useMemo
- stable callback needed? -> useCallback
- child re-render issue? -> React.memo
