    1️⃣⁡⁣⁢⁣ 𝗥𝗲𝗮𝗰𝘁.𝗺𝗲𝗺𝗼⁡

    🔧 What it is:
        - A higher-order component that prevents unnecessary re-renders by memoizing the rendered output.
        - (It’s like saying: “If props didn’t change, don’t bother re-rendering this component.”)

    Example:
    ⁡⁢⁢⁢import React from "react";

    const Child = React.memo(({ value }) => {
        console.log("Child rendered");
        return <p>Value: {value}</p>;
    });

    function App() {
        const [count, setCount] = React.useState(0);

        return (
            <div>
                <Child value="Hello" /> {/* This will not re-render when count changes */}
                <button onClick={() => setCount(count + 1)}>Increase Count</button>
            </div>
        );
    }⁡


    ✅ When to use:
        - For pure components (output depends only on props)
        - When props rarely change

    ⚠️ Don’t overuse — memoization itself has a cost.

    _______________________________________________________________________________


    2️⃣ ⁡⁣⁢⁣𝘂𝘀𝗲𝗠𝗲𝗺𝗼⁡

    🔧 What it is:
        - A hook to memoize expensive calculations so they are not recalculated on every render.

    Example:
    ⁡⁢⁢⁢import { useState, useMemo } from "react";

    function ExpensiveComponent({ numbers }) {
        const [count, setCount] = useState(0);

        const total = useMemo(() => {
            console.log("Calculating...");
            return numbers.reduce((acc, n) => acc + n, 0);
        }, [numbers]);

        return (
            <div>
                <p>Sum: {total}</p>
                <button onClick={() => setCount(count + 1)}>Re-render</button>
            </div>
        );
    }⁡


    ✅ When to use:
        - When a calculation is expensive (loops, filtering, sorting)
        - When result does not need to be recalculated unless dependencies change

    3️⃣ ⁡⁣⁢⁣𝘂𝘀𝗲𝗖𝗮𝗹𝗹𝗯𝗮𝗰𝗸⁡

    🔧 What it is:
        - A hook to memoize functions so that they are not re-created on every render.

    Example:
    ⁡⁢⁢⁢import { useCallback, useState } from "react";
    import React from "react";

    const Child = React.memo(({ onClick }) => {
        console.log("Child rendered");
        return <button onClick={onClick}>Click Me</button>;
    });

    function App() {
        const [count, setCount] = useState(0);

        const handleClick = useCallback(() => {
            console.log("Button clicked");
        }, []); // memoized function

        return (
            <>
            <Child onClick={handleClick} />
            <button onClick={() => setCount(count + 1)}>Increase Count</button>
            </>
        );
    }⁡


    ✅ When to use:
     - When passing functions as props to memoized components
     - Prevents child components from re-rendering unnecessarily

    4️⃣ ⁡⁣⁢⁣𝗥𝗲𝗮𝗰𝘁.𝗹𝗮𝘇𝘆⁡

    🔧 What it is:
        - Allows code-splitting by lazy-loading components only when needed.
        - Improves initial load time by reducing bundle size.
        - Enables dynamic imports.
        - Enhances user experience by loading components on demand.  

    Example:
    ⁡⁢⁢⁢import React, { Suspense } from "react";

    const About = React.lazy(() => import("./About"));

    function App() {
        return (
            <Suspense fallback={<p>Loading...</p>}>
                <About />
            </Suspense>
        );
    ⁡}


    ✅ Benefit:
        - ⁡⁣⁣⁢Loads components on demand, improving initial page load speed⁡.

    6️⃣ ⁡⁣⁢⁣𝗖𝗼𝗱𝗲 𝗦𝗽𝗹𝗶𝘁𝘁𝗶𝗻𝗴⁡

    🔧 What it is:

        - Concept	Purpose	When to Use
        - React.memo	Prevents unnecessary re-render if props don’t change	Pure components
