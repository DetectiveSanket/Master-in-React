⁡⁢⁣⁣𝗤) why do we need Redux if React already provides ⁡⁢⁣⁣𝘂𝘀𝗲𝗦𝘁𝗮𝘁𝗲 𝗮𝗻𝗱 𝘂𝘀𝗲𝗖𝗼𝗻𝘁𝗲𝘅𝘁?⁡
-
   ⁡⁣⁢⁣ 𝗜𝗡𝗧𝗘𝗥𝗩𝗜𝗘𝗪 𝗥𝗘𝗔𝗗𝗬 𝟭:-⁡
        - React's useState and useContext are great for managing state in small applications or within a single component tree. However, as applications grow, managing state across multiple components can become complex and lead to issues like prop drilling. Redux provides a centralized store that allows for predictable state management, making it easier to share state across different parts of the application without passing props down through many layers of components.  

    ⁡⁣⁢⁣INTERVIEW READY 2:-⁡
        - useState is mainly used for local component state. If multiple components need the same data, we can use Context to share it, but as the application grows, managing complex shared state with Context can become harder. Redux gives us a more structured and predictable way to manage application-level state, especially when we have many components and complex state updates.

⁡⁢⁣⁣𝗤) 𝗪𝗵𝗮𝘁 𝗶𝘀 𝘁𝗵𝗲 𝗱𝗶𝗳𝗳𝗲𝗿𝗲𝗻𝗰𝗲 𝗯𝗲𝘁𝘄𝗲𝗲𝗻 𝗥𝗲𝗱𝘂𝘅 𝗮𝗻𝗱 𝗖𝗼𝗻𝘁𝗲𝘅𝘁 𝗔𝗣𝗜?
⁡
    - The main difference is that Redux is a state management library that provides a centralized store for managing application-level state, while the Context API is a built-in feature of React that allows you to share state across components without prop drilling. Redux is more suitable for larger applications with complex state management needs, while the Context API is better for simpler use cases.


⁡⁢⁣⁣𝗤) 𝗪𝗵𝗮𝘁 𝗶𝘀 𝗰𝗿𝗲𝗮𝘁𝗲𝗦𝗹𝗶𝗰𝗲 𝗶𝗻 𝗥𝗲𝗱𝘂𝘅 𝗧𝗼𝗼𝗹𝗸𝗶𝘁?
⁡
    - createSlice is a Redux Toolkit function that lets us define a feature's name, initial state, and reducer functions in one place. It also automatically generates the corresponding action creators and action types, which significantly reduces Redux boilerplate.   

    - createSlice → name + initialState + reducers → automatically gives actions

⁡⁢⁣⁣Q) You said createSlice automatically creates actions. How does it create those actions from the reducers we define?”
⁡
    - When we define reducer functions inside createSlice, Redux Toolkit uses those reducer names to automatically generate the corresponding action creators and action types. So we don't have to create them manually.

Q) Okay, then what is the difference between a reducer and an action?

    - A reducer is a function that receives the current state and an action, and decides how the state should change.

    - The action contains information about what happened. It can also contain a payload with data.  

    - Def:- A reducer is a function that takes the current state and an action, and returns the updated state. The action describes what happened, and its payload can contain the data needed for the update.”

Q) 👉 “Okay, then what exactly is an action in Redux? And what do you mean by payload?”

    - In Redux, payload simply means the data carried by an action.

    - Action = what happened

    - Payload = extra data about what happened
    
    - Reducer = how state should change

    - Def:- An action describes what happened in the application. It can also contain a payload, which is the data needed to perform that state update. For example, when adding a product to a cart, addToCart can be the action and the product information can be its payload.
